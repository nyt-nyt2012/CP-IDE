# CP-IDE · C++ 竞赛编程 IDE 与评测机

一个**完全本地运行**的 C++ 竞赛编程工作台，可以**双击 `CP-IDE.exe` 直接当桌面软件用**（自带 Python 运行时与全部资源，离线可用）；也可用 `python app.py` 以网页方式跑。

界面：顶部是像浏览器一样的**多文件标签页**，编辑器可以**左右分栏对照**两段代码；右侧工作面板分为**样例调试 / 批量评测** 两个模式；底部是收成细条的编译信息区。支持一键编译、运行样例、整批评测（逐点给出耗时、内存与评测状态），并内置**基于 testlib 的自定义 checker**（testlib 库已随项目附带）、代码格式化（含格式化前后对比视图）、查找替换、编译环境配置与「在代码前插入代码」等扩展功能。界面提供深色 / 浅色两套主题。

所有打开的文件（**包括还没保存的修改**）、上一次的编译信息与界面偏好都会**自动保存到本机**，下次打开 IDE 原样恢复；当前文件也可以随时**另存到电脑**上的任意位置。

## 界面结构

```
┌────────────────────────────────────────────────────────┬──────────────┐
│ [main.cpp ×][solution.cpp ×][+]  …        N 个文件 ▥分栏 │ 样例调试     │
├───────────────────────────┬────────────────────────────┤ 批量评测     │
│  源代码（左栏）            │  对比（右栏）               │  ← 模式切换  │
│                           │                            ├──────────────┤
│  （没打开文件时显示空状态） │                            │  侧栏内容    │
├───────────────────────────┴────────────────────────────┤              │
│ 编译信息（默认折叠为一条细条 ▾ 展开 / ✕隐藏）             │              │
└────────────────────────────────────────────────────────┴──────────────┘
```

- **多文件标签页**：像浏览器一样打开 / 关闭 / 重命名多个代码文件，每个标签页有独立的撤销历史，关闭已修改的文件会先确认；标签页与内容会自动保存到本机，下次打开原样恢复
- **空状态**：刚打开 IDE 时**不会自动塞一个示例文件**，编辑区显示「当前没有打开的文件」，并提供「＋ 新建文件 / 📂 打开文件 / 📚 内置示例」三个入口
- **左右分栏对比**：点顶栏「▥ 分栏」即可左右对照两个文件，中间分隔条可拖动调整比例，支持「联动滚动」，「⇄」可把右栏文件换成当前编辑目标
- **样例调试**：输入 / 期望输出 / 程序输出三栏 + 运行按钮，用于快速验证单个用例
- **侧栏可折叠**（顶栏 ◨ 或 `Alt + H`）：把右侧样例 / 评测面板整个收起，编辑区占满整屏；分栏时两栏同步变宽，再按一次恢复
- **编译并运行**（顶栏 ⏵ 或 `Ctrl + Enter`）：一步完成「编译 → 运行当前样例」，编译失败时只报错误、不运行
- **批量评测**：上传 `.in` / `.out` / `.cfg` / `.zip`、测试点配置文件、逐点评测结果
- **设置抽屉**（顶栏 ⚙）：编译环境 / 插入代码 / 查找替换 / 外观 / **快捷键**，从右侧滑出，不占右栏空间
- **格式化视图**（顶栏 ✦）：左「原始代码」右「格式化结果」左右对照，可一键应用

## 快速开始

### 方式一：双击 `CP-IDE.exe`（推荐，纯离线桌面版）

项目根目录下的 **`CP-IDE.exe`**（约 17 MB，单文件）是打包好的桌面版：

- **不需要装 Python**，解释器和全部页面资源都封在 exe 里；
- **不需要联网**，也**不弹控制台窗口**（GUI 子系统程序，双击不会出现黑框一闪而过）；
- 双击后会自己启动本地服务器，并弹出一个**独立窗口**（内嵌 Microsoft Edge WebView2，
  不是浏览器标签页），关掉窗口即退出整个程序；
- 端口默认 5000，被占用时自动往后找空闲端口；
- 编译器仍然用本机的 winlibs g++，把 `winlibs-*.zip` 解压到桌面或 exe 旁边即可自动找到。

也可以双击 `Start CP-IDE.bat`：它会转交给无控制台的启动器
（`cp-ide/tools/launch_cpide.vbs`），因此同样**不会出现终端窗口**。

### 方式二：源码运行（需要 Python）

```bash
cd cp-ide
python app.py
```

然后访问 <http://127.0.0.1:5000/>。这种方式会在当前终端里跑服务器，按 `Ctrl+C` 即可停止。

> 如果希望服务器在后台常驻（不占用终端窗口），可以用
> `cp-ide/tools/start_server_hidden.vbs`（无控制台启动，不受窗口关闭事件影响），
> 例如交给任务计划程序调用：
> `wscript.exe "<项目路径>\cp-ide\tools\start_server_hidden.vbs"`。

> ⚠️ **不要直接双击 `templates/index.html`**。
> 直接以 `file://` 打开时，页面模板不会被渲染、样式表与脚本也无法加载，
> 页面会显示成一堆无样式的原始元素（页面会弹出提示说明正确用法）。

## 依赖

| 依赖 | 说明 |
| --- | --- |
| MinGW-w64 g++ | **必需**（编译与评测要用）。使用上级目录的 `winlibs-*.zip`；解压到桌面或 exe 旁边，IDE 会自动发现 `mingw64/bin/g++.exe`，也可用环境变量 `CPIDE_CXX` 直接指定 |

官方 **testlib v0.9.45** 已内置在 `include/testlib.h`，不需要联网也不需要另行下载。

> `Alt` 组合而不是 `Ctrl + N` / `Ctrl + W`，是因为后两者会被浏览器抢去新建 / 关闭浏览器标签。

#### 怎么改快捷键

1. 点顶栏齿轮打开**设置抽屉**，切到 **「快捷键」** 页签；
2. 点某个快捷键右侧的按键框 → 框内变成「按下按键…」，直接按新组合键；
   - 按 `Esc` 取消本次录制；
   - 按 `Backspace` 删掉这个功能的快捷键（让它没有快捷键）；
3. 同一个组合键**不允许**两个功能共用：撞键会被拒绝，并提示该键位已被谁占用；
4. 单条「恢复」还原该项默认值，「全部恢复默认」清空所有改动；
5. 改动会**随工作区一起保存**（`workspace.json` 的 `settings.shortcuts`，另有浏览器本地缓存兜底），
   下次打开 IDE 依然是你改过的键位。

> 改键后原来那个键位会自动失效，不会出现「两个功能一起触发」的情况。
> 搜索框可以按功能名 / 键名快速过滤，比如输入「查找」只会留下 4 条相关项。

## 工作区持久化与导出

### 关掉 IDE 也不会丢代码

IDE 会把「上次在做什么」写进 `%LOCALAPPDATA%\CP-IDE\workspace.json`：

- **所有打开的标签页**，包括**还没保存的修改**；
- 当前标签、左右分栏状态、正在对比的文件；
- **上一次的编译信息**（成功 / 失败、耗时、警告数、完整命令行、诊断列表）；
- 界面偏好：主题、代码字体、字号、C++ 标准与警告选项、Python 解释器路径、
  编译信息区显隐、样例调试 / 批量评测模式、**自定义快捷键**。

写入是**防抖**的：改一个字不会立刻写盘，停手约 0.6 秒后写一次；
关窗口时还会用 `sendBeacon` 再补一次，保证最后一段改动也落盘。

启动时按这个顺序恢复：

1. 读 `%LOCALAPPDATA%\CP-IDE\workspace.json`；
2. 文件不存在或读不出来时，才退回浏览器里的本地缓存（`localStorage`）；
3. 两者都没有 → **空状态**（不会自动创建一个示例文件）。

> 之前「关掉就没了」有两个原因，都已修掉：
> 一是桌面版用 pywebview 的内嵌窗口，而 `webview.start()` 默认 `private_mode=True`，
> 每次都用临时目录，浏览器侧的 `localStorage` 跟着窗口一起消失；
> 现在改成 `private_mode=False` + 固定 `storage_path`。
> 二是把**服务端的工作区文件当成主副本**，即使浏览器缓存被清掉也不影响恢复。

### 导出到电脑

| 入口 | 行为 |
| --- | --- |
| 顶栏「⬇ 导出」/ `Ctrl+S` | 弹**系统原生「另存为」对话框**，把当前文件存到电脑任意位置（按扩展名自动给出文件类型过滤） |
| 设置 →「工作区与备份」→「导出全部文件（zip）」 | 把当前所有标签页打成一个 zip 另存 |
| 设置 →「工作区与备份」→「重新载入上次的工作区」 | 手动回滚到上一次保存的状态 |

「另存为」用的是 Windows 原生的 `GetSaveFileNameW`（`core/savedialog.py`），
不依赖额外窗口，在后台线程里调用也有效；
系统不支持时（例如非 Windows）会自动退回成浏览器下载。

## 自定义 Checker（testlib）

IDE **自带官方 testlib v0.9.45**（`include/testlib.h`，约 208 KB），编译 checker 时会自动把
该目录加入头文件搜索路径，**上传测试数据时不需要再附带库文件**。

### 用法一：放进 zip（最省事）

把 `checker.cpp` 和测试数据一起打包成 zip 上传即可，IDE 会：

1. 解压后自动找出 `checker.cpp`（也认 `checker.cc` / `check.cpp` / `chk.cpp`）；
2. 把所有测试点改用这个 checker 判定，并在结果区提示「自定义 Checker: checker.cpp」；
3. 用内置 testlib 编译并运行它，`quitf` 的说明文字会显示在评测结果里。

如果 zip 里自带 `testlib.h`，会优先使用你自带的那份；没有就用内置版本。

### 用法二：在 IDE 里写

新建（或重命名）一个标签页为 **`checker.cpp`**，把代码写进去，评测时会自动使用它
（上传数据里若也有 `checker.cpp`，则优先用上传的那份）。

### checker 的写法（testlib 约定）

```cpp
#include "testlib.h"      // 内置库，无需自己附带

int main(int argc, char *argv[]) {
    registerTestlibCmd(argc, argv);   // 必须写在 main 的第一行

    while (!ans.seekEof() || !ouf.seekEof()) {
        string expected = ans.readWord();   // 标准答案
        string got = ouf.readWord();         // 程序输出
        if (got != expected) {
            quitf(_wa, "token mismatch: got '%s', expected '%s'",
                  got.c_str(), expected.c_str());
        }
    }
    quitf(_ok, "answer is correct");
}
```

- 运行方式是 `checker <输入文件> <程序输出文件> <标准答案文件>`；
- testlib 的 `inf` / `ouf` / `ans` 分别对应输入、程序输出、标准答案；
- 退出码由 testlib 决定：`_ok`→AC、`_wa`→WA、`_pe`→PE、`_fail`→其它错误。

评测面板的「自定义 Checker」区提供了「插入 checker 模板」按钮，会新建一个 `checker.cpp`
标签页并填入一份可直接使用的模板（逐 token 比较，可一键改成数值比较）。

## 关于浏览器缩放

页面布局全部使用 CSS 网格自适应，**浏览器强制缩放（Ctrl + 滚轮）不会破坏排版**：

- 编辑器高度用 `100%` 跟随容器，而不是写死的 `vh`，因此缩放后不会在代码下方残留一块空白；
- 底部编译信息区折叠后只有 32px，展开时高度用 `min(232px, 34vh)` 兜底，视口变矮时不会被挤出屏幕；
- 侧栏、模式页、设置抽屉同样使用 `minmax()` + `min()`，窄屏下自动改为整页滚动，控件不会被裁切；
- 标签栏与分栏用 `minmax(0, 1fr)` + 可拖动分隔条，窗口变窄时两栏等分，不会把代码挤出可视区；
- 外观设置里的字体与字号会同时作用于编辑器和样例输入 / 输出框。

## 重新打包 exe

打包用的配置是 `cp-ide/CP-IDE.spec`，一条命令即可：

```bat
cd cp-ide
tools\build_exe.bat
```

产物为 `cp-ide\dist\CP-IDE.exe`，脚本会顺带复制一份到项目根目录。
打包脚本会在缺依赖时自动执行 `pip install pyinstaller pywebview pythonnet`
（**这一步需要联网**，只有构建需要；生成的 exe 运行期完全离线）。

打包时有三处路径会变化，代码里由 `cp-ide/core/paths.py` 统一处理：

| 类别 | 源码运行时 | 打包成 exe 后 |
| --- | --- | --- |
| 只读资源（templates / static / include / samples） | 项目目录 | exe 解包出的临时目录 `sys._MEIPASS` |
| 可写数据（自建代码片段、临时构建目录） | `cp-ide/data`、`%TEMP%\cpide-work` | `%LOCALAPPDATA%\CP-IDE` |
| 找编译器时搜索的目录 | 项目目录及其上级 | exe 所在目录 + 桌面 + 下载目录 |

## 多语言支持

### Python（`.py`）

和 C++ 完全一样的工作流：

1. **编译** = 语法检查，出错时给出**行号列号**，在底部编译信息区里可以点击跳转；
2. **运行** = 用解释器跑脚本，标准输入 / 标准输出、耗时、内存、超时与内存限制都和 C++ 一致；
3. **评测** = 整批测试点逐个跑，答案比较方式（默认 / 严格 / 按空白 / 数值 / 自定义 checker）完全通用。

解释器默认用 IDE 自带的那个（打包成 exe 时就是 exe 自己，通过 `--cpide-run` 参数
把脚本当普通程序执行），也可以在「设置 → 编译环境」里换成任意一个 `python.exe`。

### Markdown（`.md`）与 LaTeX

- 点标题栏的 👁 在**源码**与**渲染预览**之间切换；
- 渲染用 [marked](https://github.com/markedjs/marked)，代码块用 CodeMirror 的
  runmode 按语言高亮，并可显示行号；
- 公式用 **KaTeX** 渲染：`$...$` 行内、`$$...$$` 块级、`\[...\]`、`\(...\)` 都支持，
  能覆盖 KaTeX 文档里的绝大多数命令（<https://katex.org/docs/supported.html>）；
- 为了让多行公式不被 Markdown 破坏，渲染前会**先把代码块和公式摘出来**再交给
  Markdown 处理，所以 `\\begin{pmatrix} ... \\end{pmatrix}` 这类矩阵写法可以直接用。

### 代码块的行号与语法高亮

围栏的**信息串**里可以写语言名，后面还能跟开关：

````markdown
```cpp line-numbers
#include <bits/stdc++.h>
int main() { return 0; }
```
````

- 只写语言名（` ```cpp `）→ 有语法高亮、没有行号；
- 后面加 `line-numbers`（也认 `line-numbers` / `{line-numbers}` / `{.cpp .line-numbers}` 等写法）
  → **这个代码块单独带行号**；
- 在「设置 → 外观 → Markdown 文档」里勾上「代码块显示行号」，则**所有**代码块都带行号；
- 「代码块语法高亮」开关则控制是否上色。

行号渲染成左侧一列独立数字，横向滚动代码时行号固定不动。
配色用 GitHub 风格，并跟随深色 / 浅色主题切换。

### Markdown 渲染（洛谷扩展语法全支持）

预览模式在 CommonMark / GFM 之上，补齐了
[洛谷 Markdown 格式手册](https://help.luogu.com.cn/rules/academic/handbook/markdown)
里的扩展语法：

| 语法 | 效果 |
| --- | --- |
| `:::align{center}` / `:::align{right}` | 居中 / 居右排版 |
| `:::epigraph[——otto]` | 引言（带署名） |
| `:::info[标题]` / `success` / `warning` / `error` | **折叠框**，加 `{open}` 默认展开 |
| `::::` 嵌套 | 折叠框可嵌套（最内层三个 `:`，每往外一层加一个 `:`） |
| `::cute-table{tuack}` | 更像 Tuack 的表格样式 |
| 单元格写 `^` | 向上合并单元格 |
| 单元格写 `<` | 向左合并单元格 |
| 代码块 | 右上角有语言标签 + **「复制」按钮**，并带**语法高亮**；写 `line-numbers` 可加**行号** |
| 行末两个空格 / 单个 `\` | 段落内换行 |
| 裸网址 | 自动转成链接 |
| `![](https://www.bilibili.com/video/BVxxx)` | 渲染成 B 站内嵌播放器 |
| `$...$` / `$$...$$` / `\[...\]` | LaTeX 公式（KaTeX） |

标题里也可以写公式（折叠框标题同理）。

实现上有三个坑已经处理掉：

1. **公式 / 代码块要先摘出来**再交给 Markdown 解析器，否则 Markdown 会把 LaTeX 里的
   `\\` 当成硬换行吃掉，公式直接报废；
2. **容器要先于公式提取**，否则标题里的 `$$...$$` 会把标题行拆成多行，导致
   `:::info[...]` 识别不出来；
3. **围栏的信息串不能只认一个词**：早期只允许「语言名」独占整行，于是
   ` ```cpp line-numbers ` 这种写法匹配不上，**结束围栏被当成了开始围栏**，
   后面整段正文（包括标题）被吞成一个代码块。现在信息串按「语言 + 开关」解析，
   并且**没有闭合围栏时按普通文本处理**，不会再吞正文。

渲染逻辑集中在 `static/js/md-enhance.js`，与界面其它部分解耦。

### PDF

用顶栏的 📂 打开一个 `.pdf`，就会在内置阅读器（pdf.js）里显示：

- **按原始大小渲染**（PDF 的 96 DPI，和浏览器自带 PDF 阅读器一致），
  并按屏幕设备像素比出图，**文字清晰不糊**；
- 页面比窗口高时就在下方**上下滚动**查看，和 Markdown 预览的观感一致；
- 工具栏：翻页、＋/－ 手动缩放、「100%」回到原始大小、「宽度」宽度适应窗口、
  「用系统程序打开」交给系统的默认阅读器；
- 窗口大小变化时会自动重新适配。

> 说明：这里没有采用「整页缩放到一屏」的方案——那样虽然能一屏看全，
> 但正文会被压得很小、放大后发虚；改为原尺寸渲染 + 滚动查看更清楚。

- 上传的 PDF 会缓存在 `%LOCALAPPDATA%\CP-IDE\assets`，**重启 IDE 后仍能打开**，
  源码运行与 exe 运行用的是同一份缓存。

### 关于「黑色控制台窗口」

打包后的 exe 是 GUI 程序（本身没有控制台）。编译、运行程序、跑 checker 时都会启动
控制台类子进程（g++、你自己编译的 exe、checker），Windows 默认会给它们新开一个
控制台窗口，表现为**一闪而过的黑框**。

IDE 的处理方式（`core/winflags.py`）——**分两条路径**：

- **编译器（g++ 及它派生的 cc1plus / as / ld）**：只加 `CREATE_NEW_PROCESS_GROUP`，
  配合 `STARTF_USESHOWWINDOW + SW_HIDE` —— 控制台照常创建（这样子进程能继承同一个
  隐藏的控制台），但窗口不显示；**刻意不加 `CREATE_NO_WINDOW`**，否则 g++ 自己就没有
  控制台了，它派生的 cc1plus 会各自新建一个可见控制台，黑框反而照样会闪出来；
- **运行你自己编译的程序、checker、Python 脚本、以及收尾用的 `taskkill`**：这些
  根本不需要控制台，直接加 `CREATE_NO_WINDOW` —— **压根不分配控制台窗口**，
  比「先创建再隐藏」更彻底，连闪一下的机会都没有。

这样编译、运行、评测全过程都不会再出现黑框。

## 常见问题

**Q：页面排版全乱？**
A：多半是用 `file://` 直接打开了 `templates/index.html`。请通过
`http://127.0.0.1:5000/` 访问，或双击 `Start CP-IDE.bat`。

**Q：提示「未找到 C++ 编译器 g++」？**
A：把 `winlibs-*.zip` 解压到任意目录，IDE 会在项目目录、桌面等位置自动搜索
`mingw64/bin/g++.exe`；也可以设置环境变量 `CPIDE_CXX` 直接指定编译器路径。

**Q：项目放在含中文的路径下会不会有问题？**
A：不会。MinGW 的 `ld.exe` 无法在含中文的路径下写出可执行文件，IDE 检测到后
会自动把构建目录迁移到 `%TEMP%\cpide-work`。

**Q：自定义 checker 怎么写？**
A：见上面「自定义 Checker（testlib）」一节。要点只有两条：`main` 第一行调用
`registerTestlibCmd(argc, argv)`，并且用 testlib 打开的 `ouf` / `ans` 读取数据。
IDE 已内置官方 testlib v0.9.45，写 `#include "testlib.h"` 即可，不必上传库文件。

**Q：上传了 zip 却没有自动启用 checker？**
A：确认压缩包里的文件名是 `checker.cpp`（或 `checker.cc` / `check.cpp` / `chk.cpp`），
并且它位于压缩包根目录或任意子目录都可以（解压时会自动展开）。评测面板会显示
「已识别 checker.cpp」；若提示未识别，请查看编译信息区里的 checker 编译错误。

**Q：标签页怎么整理？**
A：双击标签名可就地重命名；「✕」关闭（文件改过会先弹确认条）；
顶栏「📄」把当前文件重置为内置示例代码；标签过多时标签栏会横向滚动。

**Q：想让代码用别的字体？**
A：点顶栏 ⚙ 打开设置抽屉 →「外观」，每张卡片都会用真实字体渲染一段示例代码；
系统没装的字体会自动回退到下一个可用字体。字号、主题、编译信息区显隐也在同一页。

**Q：隐藏编译信息后怎么再看编译结果？**
A：右下角会浮出「▲ 编译面板」按钮，点它即可恢复；隐藏期间若有新编译结果，
该按钮会以呼吸高亮提示你。也可以在「外观」页取消「完全隐藏编译信息」勾选。

**Q：编译信息太占地方？**
A：默认就是折叠的细条（32px），点 ▾ 展开正文；只有编译失败时会自动展开，
方便你第一时间看到错误位置。

**Q：关掉 IDE 之后代码还在吗？**
A：在。IDE 会把标签页内容（**包括没保存的修改**）、上次的编译信息与界面偏好
自动写进 `%LOCALAPPDATA%\CP-IDE\workspace.json`，下次打开自动恢复。
如果想手动回滚，去「设置 → 工作区与备份 → 重新载入上次的工作区」。

**Q：怎么把代码存到电脑上？**
A：顶栏「⬇ 导出」（或 `Ctrl+S`）会弹系统的「另存为」对话框，选好位置即可；
「设置 → 工作区与备份 → 导出全部文件（zip）」可以把所有标签页打成一个压缩包。

**Q：为什么打开 IDE 是空的，什么文件都没有？**
A：这是有意为之——启动时**不会自动塞一个示例文件**进来。
编辑区会显示「当前没有打开的文件」，点「＋ 新建文件」「📂 打开文件」
或「📚 内置示例」即可开始。

**Q：`%TEMP%\cpide-work` 里的临时目录会越堆越多吗？**
A：不会。每次编译 / 运行 / 评测都会在 `%TEMP%\cpide-work` 下建一个临时目录（编译产物、
标准输入输出缓存都在里面）：
- IDE **正常退出**时，会自动删掉本次运行创建的全部临时目录；
- 万一上次是被强杀（任务管理器结束、断电），**下次启动时 IDE 会顺手清理过期 3 小时的残留**，
  不会越攒越多。

**Q：编译成功了，但运行时提示「系统拒绝启动这个程序」或「要运行的文件不见了」？**
A：这是**杀毒软件把刚编译出来的 exe 拦了 / 直接隔离删掉了**（国产安全卫士对
「刚生成的可执行文件」特别积极，死循环类的程序尤其容易被误伤）。
IDE 会自动重试几次；仍然不行时会明确告诉你原因。解决办法任选其一：
把工作目录换到安全软件不扫描的位置、给编译产物所在目录加信任、或临时关掉实时防护。

**Q：Markdown 里的代码块怎么加行号？**
A：在围栏后面写 `line-numbers`，例如 ` ```cpp line-numbers `；
想让所有代码块都带行号，去「设置 → 外观 → Markdown 文档」勾上「代码块显示行号」。
